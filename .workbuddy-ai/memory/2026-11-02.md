# 2026-11-02 — Role model investigation (why still teacher)

- Teacher role is **not stored anywhere** — it is re-derived from Discord at login only:
  `resolvePrincipal()` → `isDiscordAdmin()` → true if (a) Discord user ID === `ADMIN_ROLE_ID`,
  (b) guild owner, (c) member has Administrator permission, (d) member has role `ADMIN_ROLE_ID`.
- `createBrowserSession()` bakes `role` into the signed 8h session cookie and `getBrowserSession()`
  never re-resolves it → **role changes only apply after logout + login** (or 8h expiry).
- This deployment: `ADMIN_ROLE_ID=776347489275084802` is the owner's **user ID** (`hyprblue.zx`),
  not a role — verified it matches no role in guild `MEP4 กุให้หมด`; that user is not guild owner
  and none of their 4 roles has Administrator. So the user-ID match is the only reason for teacher.
- Guild role with Administrator permission: `MEP kuy rai sus` (1508325595287650368) — holding it
  also forces teacher. Guild owner (1269602059703943230) is always teacher.
- No in-app teacher assignment/demotion exists (TeacherUsersPage only manages students/presidents).
  Changing teacher = change `ADMIN_ROLE_ID` (Vercel env + redeploy) or change Discord roles.

## Timetable → Subjects sync (new feature)

User reported: importing a timetable from Sheets saved cells but never created Subjects, so homework
could not reference those codes ("Subject not found").

- `timetableService.createMissingSubjects(term, schoolYear)` — reads timetable + Subjects, normalises
  codes, dedupes (prefers a cell that has a name/instructor), writes all missing rows in ONE
  `batchAppend`; `needsReview=true` when no name was found. Idempotent.
- Exposed as `POST /api/timetable/sync-subjects` (president/teacher, CSRF-protected) and as an
  optional `createMissingSubjects` flag on `POST /api/timetable/batch` and
  `POST /api/timetable/imports/:id/confirm`.
- UI: "ซิงก์วิชาจากตารางเรียน" button in the timetable header + "สร้างวิชาที่ยังไม่ในระบบ" checkbox
  (default on) in both import previews; result shown via a `role="status"` notice.
- Also fixed in the paste parser: period/day column detection was per-row (`row.length > 5`), which
  shifted every cell when a narrow range (e.g. Mon–Wed) was pasted. Now decided once per block by
  majority of rows, so partial pastes align correctly.
- Verified: stub-sheet unit test, route test (403 for students, idempotent re-sync), and a full
  headless-Chrome run (paste → parse → save → notice "เพิ่มวิชาใหม่ N รายวิชา", Subjects page shows them).
