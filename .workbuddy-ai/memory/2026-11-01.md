# 2026-11-01 — Pre-launch bug hunt (emble-web)

Full-stack bug pass before shipping. `tsc`, `node -c` lint and `vite build` all pass at the end.

## Fixed

- **src/services/timetableImportService.js** — `createImport` referenced `ocrResult` in the draft object, but that variable only exists in the Cloud Vision branch. Every Gemini OCR import (the default path) threw `ReferenceError` → 500. Now uses the `blockCount` / `ocrConfidence` values computed per branch.
- **src/server/routes/teacher.js** — `PATCH /api/teacher/settings` read rows with `readSheet` (no `_rowIndex`) so it always appended duplicate settings rows. Now uses `readSheetWithRows`.
- **client/api/client.ts** — `push.unsubscribe()` sent a DELETE with no body while the API requires `{ endpoint }` → every "disable notifications" failed with 400. `delete()` now accepts an optional body.
- **src/app.js** — attachment and push routers were mounted without `csrfProtection` although they expose POST/DELETE. Added.
- **src/services/authService.js** — `resolvePrincipal` (Discord OAuth path) did not reject `isActive === 'false'` users, so deactivated students could still sign in. Added guard.
- **public/sw.js** — no `push` / `notificationclick` listeners, so push subscriptions could never display a notification. Added both; cache bumped to `emble-shell-v2`.
- **src/server/routes/auth.js + userService.js** — Discord "link account" flow was a stub that fell through to a normal login (could sign you in as another student). Now: link starts from the verified session (`?link=1`), callback writes `discordId` via `linkDiscordAccount` (409 if already linked elsewhere), re-issues the session cookie, redirects to `/account?link_status=linked`.
- **src/server/integrations/discordOAuth.js** — OAuth `state` was kept in an in-memory Map, which breaks on Vercel when the callback hits another lambda instance (`oauth_invalid_state`). Now HMAC-signed + expiring, stateless.
- **client/pages/LoginPage.tsx + App.tsx** — server redirects OAuth failures to `?login_error=…` but nothing consumed them (ProtectedRoute dropped the query string). Errors now surface on the login page.
- **src/services/homeworkService.js** — `status=pending` included completed items; now `!isOverdue && !completed`.
- **client/pages/DashboardPage.tsx** — "Pending" stat used `analytics.pendingCount` (includes completed → double counts with doneCount). Now uses `todoCount`.
- **src/utils/dates.js** — `hour12: false` can format midnight as `24:00`; switched to `hourCycle: 'h23'` so values round-trip through `parseBangkokDate`.
- **src/services/attachmentService.js** — attachment rows used `USER_ENTERED`; user-supplied filenames could be evaluated as formulas. Now `appendRowRaw`.
- **src/utils/auth.js / discordOAuth.js** — cleanup intervals now `.unref()` so they don't hold the process open.
- **README.md** — deploy/local-dev instructions pointed at a non-existent `web/` folder and `npm run build:web`.
